# Документация `Bulls and Cows`

## 1. Структуры данных и алгоритмы

## Архитектура состояния игры и истории попыток

В приложении используется **однонаправленный поток данных** (Unidirectional Data Flow), где состояние является единым источником правды (_Single Source of Truth_). Архитектура исключает прямые мутации данных, опираясь на принципы функционального программирования и строгую типизацию TypeScript.

### 1. Архитектурная схема структур данных (Снимок состояния)

Для описания игровых доменных моделей используются интерфейсы со строгими модификаторами `readonly`. Это гарантирует защиту данных как на этапе компиляции TypeScript, так и в рантайме JavaScript:

```typescript
export interface AttemptEntry {
  readonly guess: string;
  readonly bulls: number;
  readonly cows: number;
}

export interface GameSettings {
  readonly length: number;
  readonly base: Base;
}

export interface GameState {
  readonly isSettingsPhase: boolean;
  readonly settings: GameSettings;
  readonly secret: string;
  readonly startTime: number | null;
  readonly endTime: number | null;
  readonly isWon: boolean;
  readonly attempts: readonly AttemptEntry[];
}
```

### 2. Архитектурное обоснование выбора структур

#### 🛡️ Глубокая иммутабельность (Immutability)

- **Выбор структуры:** Объект состояния `GameState` и вложенный массив ходов `readonly AttemptEntry[]`.
- **Обоснование:** Вместо императивной модификации свойств или использования мутирующих методов (таких как `Array.prototype.push`), функции трансформации состояния всегда возвращают **абсолютно новый объект** с новыми ссылками в памяти. Массивы и объекты принудительно защищаются через `Object.freeze()`. Это делает поведение программы предсказуемым, исключает побочные эффекты и предотвращает баги, связанные с рассинхронизацией UI и внутренней памяти.
- **Пример из кода (Чистая функция обновления стейта):**
  ```typescript
  export const makeGuess = (state: GameState, payload: GuessPayload): GameState => {
    if (state.isWon) return state;

    const { attempt, currentTime } = payload;
    const isWonRound = attempt.bulls === state.settings.length;

    return Object.freeze({
      ...state,
      isWon: isWonRound,
      endTime: isWonRound ? currentTime : state.endTime,
      // Создается новый массив через спред-оператор взамен метода .push()
      attempts: Object.freeze([...state.attempts, attempt]),
    });
  };
  ```

#### 📈 Оптимизация по скорости и константное время $O(1)$ для алфавитов

- **Выбор структуры:** `Readonly<Record<Base, ReadonlySet<string>>>` для глобального справочника систем счисления.
- **Обоснование:** Применение структуры `Set` вместо строк или классических массивов позволяет выполнять проверку вхождения символов через метод `Set.prototype.has()` за **константное время $O(1)$**. Движку V8 не требуется сканировать массив или строку циклом в поисках совпадения при каждом нажатии клавиши игроком в поле ввода, что гарантирует мгновенный отклик интерфейса.
- **Пример из кода (Высокопроизводительный валидатор символов):**
  ```typescript
  export const ALPHABETS: Readonly<Record<Base, ReadonlySet<string>>> = Object.freeze({
    [Base.Bin]: new Set('01'),
    [Base.Oct]: new Set('01234567'),
    [Base.Dec]: new Set('0123456789'),
    [Base.Hex]: new Set('0123456789abcdef'),
  });

  export const createDigitValidator = (base: Base): CharValidator => {
    const alphabet = ALPHABETS[base];
    // Метод .has() работает за O(1) в хэш-таблице множества
    return (char: string): boolean => char.length === 1 && alphabet.has(char.toLowerCase());
  };
  ```

#### 🔒 Защита от XSS-уязвимостей на уровне хранения данных

- **Выбор структуры:** Использование примитивного строкового типа `string` для хранения попыток (`guess`) и secrets.
- **Обоснование:** Разделение текстовых данных в стейте и их последующий рендеринг через нативное свойство DOM-узлов `.textContent` (вместо небезопасного свойства `innerHTML`) полностью исключает возможность проведения XSS-атак (Cross-Site Scripting). Даже если пользователь попытается ввести вредоносный скрипт, движок браузера отобразит его как обычную текстовую строку, не выполняя код.
- **Пример из кода (Безопасная отрисовка строк лога ходов):**
  ```typescript
  props.attempts.forEach((attempt, index) => {
    const row = document.createElement('div');
    row.className = 'attempt-row';

    const cellGuess = document.createElement('span');
    cellGuess.className = 'cell-guess';

    cellGuess.textContent = attempt.guess;

    row.appendChild(cellGuess);
    attemptsLog.appendChild(row);
  });
  ```

## Алгоритм расчета результатов попытки (evaluateGuess)

Функция `evaluateGuess` является математическим ядром игры. Её задача — сравнить строку-попытку игрока (`guess`) с загаданным секретным числом (`secret`) и подсчитать количество:

- **Быков (Bulls):** цифр, которые угаданы верно и стоят на своих исходных позициях.
- **Коров (Cows):** цифр, которые присутствуют в секретном числе, но находятся на других позициях.

Функция работает в **регистронезависимом режиме** (что критично для шестнадцатеричной системы `Hex`) и возвращает глубоко замороженный объект результата.

### 1. Реализация и логика расчета

Алгоритм функции `evaluateGuess` построен на декларативных методах массивов и использует структуру `Set` для ускорения поиска:

```typescript
export interface GuessResult {
  readonly bulls: number;
  readonly cows: number;
}

export const evaluateGuess = (secret: string, guess: string): GuessResult => {
  // Иммутабельно готовим массивы символов в нижнем регистре
  const [secretChars, guessChars] = [secret, guess].map((word) => word.toLowerCase().split(''));

  // Создаем хэш-таблицу для мгновенного поиска символов секрета
  const secretSet = new Set(secretChars);

  // 1. Считаем Быков: совпадение символов под одинаковыми индексами
  const bulls = guessChars.filter((char, index) => char === secretChars[index]).length;

  // 2. Считаем общее количество совпадений через поиск в Set за O(1)
  const totalMatches = guessChars.filter((char) => secretSet.has(char)).length;

  // 3. Коровы — это все совпавшие символы за вычетом тех, что стали Быками
  const cows = totalMatches - bulls;

  return Object.freeze({ bulls, cows });
};
```

### 2. Оценка сложности алгоритма (Big O)

Пусть $N$ — длина секретного числа (в рамках правил игры составляет от 2 до 6 символов).

**Временная сложность: строго $O(N)$**

1. Подготовка массивов символов и создание `new Set(secretChars)` занимают линейное время $O(N)$.
2. Первый цикл `.filter()` (подсчет быков) делает ровно $N$ итераций с константной проверкой символов по индексу за $O(1)$.
3. Второй цикл `.filter()` (общие совпадения) делает ровно $N$ итераций, где метод `secretSet.has(char)` выполняет поиск в хэш-таблице за константное время **$O(1)$** (в отличие от метода строк `.includes()`, который сканировал бы подстроку за линейное время).

   Итоговая временная сложность линейна: $O(N) + O(N) + O(N) = \mathbf{O(N)}$.

## Расчет комбинаторной емкости игры (countPossibleSecrets)

Функция `countPossibleSecrets` отвечает за математический подсчет всех возможных уникальных секретных чисел для выбранной длины (`length`) и системы счисления (`base`).

Поскольку секретное число состоит из уникальных цифр без повторений, а лидирующий ноль разрешен правилами игры, эта задача сводится к вычислению **размещений без повторений** из множества размера $B$ ($base$) по $L$ ($length$) элементов. Математическая формула:
$$P(B, L) = \frac{B!}{(B - L)!}$$

### 1. Реализация, рекурсия и мемоизация

Для реализации используется чистая рекурсивная связь: $P(B, L) = B \times P(B - 1, L - 1)$, дополненная абстрактной функцией высшего порядка `memoize` для кэширования результатов.

```typescript
/**
 * Чистая рекурсивная функция для расчета размещений без повторений.
 * Содержит защитные барьеры от некорректных данных и бесконечного стека вызовов.
 */
export const calculatePermutations = (currentLength: number, currentBaseNumber: number): number => {
  if (currentLength < 0) return 0;
  if (currentLength === 0) return 1; // Базовый случай рекурсии
  if (currentLength > currentBaseNumber) return 0; // Невозможно набрать уникальные символы

  // Рекурсивный шаг
  return currentBaseNumber * calculatePermutations(currentLength - 1, currentBaseNumber - 1);
};

/**
 * Экспортируемая мемоизированная функция.
 * Инкапсулирует вычисления и мгновенно возвращает кэшированные ответы при повторных вызовах.
 */
export const countPossibleSecrets = memoize((length: number, base: Base): number => {
  const baseNumber = BASES[base];
  return calculatePermutations(length, baseNumber);
});
```

### 2. Принцип работы мемоизации

Функция `memoize` оборачивает вычислительное ядро и создает изолированное хранилище (`Map`) внутри замыкания.
При первом («холодном») вызове для определенной пары параметров (например, `length: 4`, `base: Base.Dec`) запускается рекурсивный расчет, результат которого сохраняется под строковым или сериализованным ключом. При всех последующих («горячих») вызовах функция полностью игнорирует рекурсию и мгновенно возвращает готовое число из памяти, снижая нагрузку при частых переходах пользователя на экран настроек.

### 3. Оценка сложности алгоритма (Big O)

Пусть $L$ — запрашиваемая длина секретного числа (в рамках игры составляет от 2 до 6).

**Временная сложность:**

- **При первичном вызове (Холодный кэш): $O(L)$**
  Глубина рекурсии строго линейна и зависит от длины числа $L$, так как на каждом шаге `currentLength` уменьшается на 1 до базового случая (`0`). Все операции на каждом шаге рекурсии выполняются за константное время $O(1)$.
- **При повторнум вызове (Горячий кэш): $O(1)$**
  Благодаря мемоизации поиск и извлечение данных из кэш-карты занимают константное время.

## Оценка сложности алгоритма `generateSecret` (Big O)

Пусть $L$ — требуемая длина секретного числа (от 2 до 6), а $B$ — размер алфавита выбранной системы счисления ($B \in \{2, 8, 10, 16\}$).

#### ⏱️ Временная сложность (Time Complexity)

- **В лучшем и среднем случае: $O(L^2)$ в теории, фактически $O(1)$**

  В идеальном сценарии источник `random` выдает уникальные индексы без повторений, и функция совершает ровно $L$ успешных шагов рекурсии. На каждом шаге метод `currentSecret.includes(nextDigit)` сканирует накапливаемую строку длиной от $0$ до $L-1$. Суммарное время проверок образует арифметическую прогрессию, что дает теоретическую сложность $O(L^2)$. Однако, поскольку максимальная длина числа жестко ограничена правилами игры ($L \le 6$), в рантайме алгоритм выполняется за доли микросекунды, что эквивалентно константному времени $O(1)$.

## Оценка сложности алгоритма `isValidGuess` (Big O)

Пусть $L$ — ожидаемая длина числа (от 2 до 6), а $G$ — длина проверяемой строки.

#### ⏱️ Временная сложность (Time Complexity): строго $O(L)$, фактически $O(1)$

1.  **Ранний возврат $O(1)$:** Проверки типа `guess.length !== length` мгновенно отсекают невалидные строки, не запуская тяжелые вычисления. Далее гарантировано $G = L$.
2.  **Проверка алфавита $O(L)$:** Создание массива `.split('')` и обход через `.every()` выполняют ровно $L$ шагов. На каждой итерации вызов `alphabet.has()` в хэш-таблице `Set` отрабатывает за константное время **$O(1)$** [1.1].
3.  **Контроль уникальности $O(L)$:** Конструктор `new Set()` обходит строку за линейное время $O(L)$ [1.1], а чтение свойства `.size` занимает $O(1)$.

Итоговая сложность шагов: $O(1) + O(L) + O(L) = \mathbf{O(L)}$. Из-за жесткого лимита игры ($L \le 6$) в рантайме функция выполняется мгновенно за константное время $O(1)$.

## Принципы Чистого Кода (Clean Code)

В ходе разработки архитектуры приложения принципы **Clean Code** были заложены в качестве фундаментальных правил кодовой базы. Каждое инженерное решение подкреплено конкретной изоляцией логики.

### 1. Принцип DRY (Don't Repeat Yourself — Не повторяйся)

- **Где применен:** модули `isValidGuess.ts` и `renderGameScreen.ts`.
- **Реализация:** Устранено дублирование алгоритмов проверки алфавитов. Комплексный валидатор строки ввода и UI-перехватчик нажатий клавиш клавиатуры переиспользуют одну и ту же каррированную фабрику предикатов `createDigitValidator(base)`, которая выступает единым источником правды.

### 2. Принцип KISS (Keep It Simple, Stupid — Делай проще)

- **Где применен:** функции `evaluateGuess` и `isValidGuess`.
- **Реализация:** Отказ от сложных вложенных императивных циклов `for/while` со счетчиками. Математическая сверка результатов и валидация построены на декларативных методах массивов (`.filter()`, `.every()`) и структурах `Set`. Код читается как чек-лист сверху вниз.

### 3. Принцип маленьких функций (Small Functions / Катомизация)

- **Где применен:** функции `createDigitValidator`, `generateSecret`, `formatDuration`.
- **Реализация:** Каждая функция ограничена одной областью ответственности (_Do One Thing_) и содержит минимальный уровень вложенности. Тяжелые циклические или инфраструктурные алгоритмы декомпозированы на независимые утилиты, не превышающие 10–15 строк.

### 4. Принцип единой ответственности (SRP)

- **Где применен:** модули `leaderboardService.ts` и `renderLeaderboard.ts`.
- **Реализация:** Полное разделение инфраструктурного слоя и слоя отображения. Функции сервиса занимаются исключительно дисковыми операциями ввода-вывода с `localStorage` и сортировкой данных в памяти, ничего не зная о DOM. Компонент `renderLeaderboard` принимает готовые данные и отвечает только за конструирование разметки.

### 5. Неизменяемость данных (Immutability)

**Суть:** Состояние системы никогда не мутирует напрямую. Вместо изменения существующих объектов или массивов в памяти (операциями вроде `obj.prop = value` или `array.push()`), любые трансформации создают **абсолютно новые копии структур данных** с обновленными ссылками. Это гарантирует предсказуемость программы, исключает побочные эффекты (_side effects_) и обеспечивает потоковую безопасность данных.
**Функции:** `startGame`, `makeGuess`, `resetToSettings`, `saveRecord`.
